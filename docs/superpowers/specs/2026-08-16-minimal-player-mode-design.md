# 极简播放器模式设计

## 背景与目标

现有用户脚本只有“圆形悬浮按钮”和“完整播放器面板”两种界面。完整面板适合管理歌单和编辑歌曲，但持续播放时占用空间较多。

本功能新增一个不超过 400 px 的单行极简播放器。它保留播放期间最常用的控制，同时隐藏封面、插件名称、版本号、线性进度条和时间文本。用户随时可以展开回完整面板，不改变现有播放状态。

## 已选方案

采用固定单行控制方案。纯音频、播放模式、上一首、播放/暂停、下一首、音量、展开和关闭始终可见，不使用悬停隐藏或“更多”菜单。

## 界面规格

- 极简播放器宽度为 `min(396px, calc(100vw - 24px))`，标准高度为 `56px`，任何情况下均不得超过 `400px`。
- 整体保持单行，不换行。
- 使用现有深色背景、边框、文字色和 Bilibili 粉色强调色。
- 不显示封面、插件图标、`Bilibili 音乐播放器`、版本号、当前时间或总时长。
- 左侧信息区显示两行：歌曲标题和作者。文本超出时省略，悬停显示完整内容。
- 控件顺序固定为：歌曲信息、纯音频、播放模式、上一首、播放/暂停及环形进度、下一首、扬声器及音量滑杆、展开、关闭。
- 播放/暂停按钮位于只读环形进度中央。粉色圆弧表示已播放部分，灰色圆环表示剩余部分。
- 完整面板标题栏新增“进入极简模式”按钮，位于“重置图标和播放器位置”与“收起播放器”之间。
- 极简模式按钮使用表示单行播放器的图标，`title` 和 `aria-label` 均为“进入极简模式”。

## 显示状态与切换

播放器有三个显示状态：

1. `launcher`：圆形悬浮按钮。
2. `full`：完整播放器面板。
3. `minimal`：单行极简播放器。

切换规则：

- 完整面板的极简模式按钮将 `full` 切换为 `minimal`。
- 极简播放器的展开按钮将 `minimal` 切换为 `full`。
- 完整和极简界面的关闭按钮都切换为 `launcher`。
- 从 `launcher` 打开时，恢复上一次使用的 `full` 或 `minimal`。
- 页面刷新后仍记住上一次打开模式；首次使用或旧数据缺少该字段时默认打开 `full`。
- 切换界面只改变显示形态，不停止播放、不跳转时间、不改变播放模式、音量或纯音频状态。

## 位置与拖动

- 完整面板和极简播放器共用现有 `panel` 位置，不分别保存坐标。
- 极简播放器可通过歌曲信息区和不属于交互控件的空白背景拖动。
- 在按钮、音量滑杆及其他交互元素上按下时不得触发拖动。
- 切换显示形态时保持面板左上角位置；如果尺寸变化导致界面超出视口，则将其限制回可见区域。
- 拖动后的坐标继续由现有布局存储保存，刷新页面后恢复。

## 控件行为

### 歌曲信息

- 标题和作者始终反映播放器运行状态中的当前项目。
- 没有可用媒体时标题行显示“等待播放器”，作者行隐藏。
- 信息区不绑定播放或展开动作，避免拖动时误触。

### 纯音频

- 复用现有纯音频控制器及其切换逻辑。
- 点击后按现有行为保存选择并重新加载页面。
- 重新加载后恢复极简模式及原面板位置。
- 检测中显示呼吸状态；生效时显示启用色；失败回退时显示红色。
- 失败回退时，鼠标悬停或键盘聚焦显示现有的具体回退原因。

### 播放模式

- 复用现有顺序：顺序播放、列表循环、单曲循环、随机播放。
- 每次点击切换到下一模式，图标和辅助文本同步更新。
- 悬停或键盘聚焦时显示当前模式名称。

### 上一首与下一首

- 完全复用现有歌单队列和边界规则。
- 没有可切换的当前媒体时按钮处于禁用状态。

### 播放、暂停与环形进度

- 点击圆心只切换播放和暂停。
- 环形进度仅显示，不响应点击或拖动。需要跳转播放位置时，用户展开完整面板使用线性进度条。
- 歌单歌曲以其 `startTime` 为 0%，以 `endTime` 为 100%；如果没有 `endTime`，使用当前媒体时长或存储时长。
- 普通视频以 0 秒为起点，以媒体总时长为终点。
- 计算结果限制在 `0%–100%`。缺少有效时长、终点不晚于起点或数值无效时显示空环。

### 音量

- 保留现有“扬声器图标 + 横向滑杆”结构和样式。
- 点击扬声器切换静音；滑动范围控制音量。
- 音量及静音状态与完整面板同步，切换界面时不重置。

### 展开与关闭

- 展开按钮返回完整面板。
- 关闭按钮收起为圆形悬浮按钮，并保留 `minimal` 作为下次打开模式。

## 状态反馈与异常处理

- 正常操作依靠按钮图标、颜色和按下状态反馈，不额外显示通知。
- 浏览器阻止自动播放且需要用户操作时，在极简播放器下方显示不改变播放器尺寸的临时提示“点击继续播放”；点击提示复用现有重试播放行为。提示最多显示 5 秒，播放状态恢复时立即消失。
- 纯音频失败不展开完整面板，通过红色耳机图标及悬停或聚焦提示说明原因。
- 没有找到 Bilibili 媒体时，播放、上一首和下一首禁用，环形进度显示空环。
- 进入 Bilibili 网页全屏时沿用现有逻辑隐藏整个插件；退出后恢复进入全屏前的显示状态和位置。
- 视口尺寸变化时重新限制播放器位置，确保其仍在可见区域内。

## 键盘与无障碍

- 所有按钮和音量滑杆可通过 `Tab` 聚焦。
- `Enter` 或空格触发聚焦按钮的既有操作。
- 所有图标按钮提供明确的 `title` 和 `aria-label`；纯音频按钮保留 `aria-pressed`。
- 播放/暂停、播放模式和纯音频标签随状态更新。
- 环形进度作为只读进度状态暴露当前百分比，但不进入独立的键盘操作序列。
- 保留清晰的键盘焦点样式，并尊重 `prefers-reduced-motion`。
- 不增加全局快捷键，避免与 Bilibili 播放器快捷键冲突。

## 内部结构

### 显示模式状态

将当前 `panelOpen` 布尔状态替换为能够表达 `launcher`、`full` 和 `minimal` 的显示状态。另行保存最后一次非关闭模式，使关闭到 `launcher` 后仍可恢复正确界面。

在现有布局数据中增加可选的 `lastOpenMode: "full" | "minimal"`。缺少该字段时使用 `full`，因此现有版本数据可以原样兼容，不需要丢弃已保存坐标。

### 界面组件

- 完整面板继续负责歌曲管理、编辑、线性进度和全部状态信息。
- 新增极简播放器组件，只负责单行布局与绑定现有播放器操作。
- 将播放/暂停、纯音频、播放模式和音量等重复控制提取为小型共享组件或共享渲染函数，确保两种面板使用相同状态和回调。
- 新增只读环形进度组件；它只接收起点、终点和当前位置并输出已限制的百分比显示。
- 极简界面只调用播放器引擎的现有公开操作，不改动播放器引擎、队列算法或纯音频拦截机制。

## 数据流

1. `App` 从现有 store、播放器引擎和纯音频控制器读取状态。
2. 当前显示模式决定渲染悬浮按钮、完整面板或极简播放器。
3. 两种播放器面板向同一组引擎和 store 操作发送事件。
4. 播放器运行状态更新后，同时驱动标题、图标、音量和进度显示。
5. 模式变化与拖动位置写入布局存储；媒体播放数据仍由现有数据存储管理。

## 测试范围

### 单元测试

- 旧布局数据缺少 `lastOpenMode` 时默认使用 `full`，并保留原坐标。
- `lastOpenMode` 只接受 `full` 和 `minimal`，无效值回退到 `full`。
- 环形进度覆盖普通视频、歌单片段、未知时长、终点不晚于起点、负数、非有限值以及上下界限制。

### Playwright 测试

- 完整面板按钮位于重置和关闭之间，并可进入极简模式。
- 极简播放器的展开、关闭和悬浮按钮恢复流程正确。
- 刷新后恢复最后一次打开模式。
- 完整和极简面板共用拖动位置，切换和视口变化后保持可见。
- 极简播放器保持单行且宽度不超过 `396px`。
- 标题、作者、省略显示和完整文本提示正确。
- 播放、暂停、上一首、下一首、播放模式、纯音频、静音和音量控制调用现有行为。
- 环形进度正确反映普通视频及歌单片段，且无法用于拖动跳转。
- 纯音频检测、启用、失败颜色及具体原因提示正确。
- 自动播放被阻止时显示可操作提示，点击后重试。
- 网页全屏隐藏及退出恢复行为保持不变。
- 键盘聚焦和 `Enter`、空格操作正常，不把快捷键事件泄漏给页面播放器。

### 完整验证

- 运行类型检查、单元测试、Playwright 测试、用户脚本构建和构建审计。

## 非目标

- 极简模式不提供歌单选择、歌曲添加、编辑或删除。
- 环形进度不支持定位播放位置。
- 不增加全局媒体快捷键、系统媒体会话或浏览器间数据同步。
- 不修改 Bilibili 章节读取功能、歌曲存储结构或队列语义。
- 不增加新的 `@grant` 或第三方依赖。
